# 포지션 적합성 체크리스트

## 1. 경력 전체 커버리지

### 1.1 경험 누락 검증
- [ ] 모든 재직 경력이 experience에 포함됨 (의도적 생략 제외)
- [ ] 각 경력의 주요 프로젝트가 빠짐없이 기재됨
- [ ] 프리랜서/계약직 경험이 있다면 적절히 포함
- [ ] 사이드 프로젝트/오픈소스 기여가 관련성 있으면 포함

### 1.2 기술 누락 검증
- [ ] 실제 사용한 핵심 기술이 techStack에 모두 포함
- [ ] Skills 섹션이 experience의 기술을 포괄
- [ ] 최신 기술 트렌드 반영 (현재 시장에서 요구하는 기술)
- [ ] 레거시 기술이 과도하게 강조되지 않음

### 1.3 성과 누락 검증
- [ ] 각 경력의 핵심 성과가 highlights에 반영됨
- [ ] 정량적 성과가 있는데 누락된 항목 없음
- [ ] 리더십/멘토링 경험이 있다면 반영됨
- [ ] 비즈니스 임팩트가 큰 성과가 우선 포함됨

## 2. 도메인별 균형

### 2.1 도메인 분포 분석
- [ ] 경력에 포함된 도메인 목록 식별 (교육, 헬스케어, 임상, 게임, SI 등)
- [ ] 각 도메인의 비중(경력 기간, 프로젝트 수)이 적절
- [ ] 주력 도메인이 명확히 드러남
- [ ] 도메인 다양성이 "적응력"으로 읽히는지, "방향성 없음"으로 읽히는지 판단

### 2.2 도메인 전문성 깊이
- [ ] 주력 도메인에서 2개+ 경력/프로젝트 존재
- [ ] 도메인 특화 용어/지식이 details에 반영됨 (예: MFDS, 임상시험, LMS)
- [ ] 도메인 전환 시 기술적 연결고리가 설명됨
- [ ] 각 도메인에서의 성과가 해당 도메인 맥락에서 의미 있음

### 2.3 도메인-포지션 정렬
- [ ] 타겟 포지션의 도메인과 경력 도메인이 연결됨
- [ ] 도메인 무관 포지션이라면 "기술 깊이"가 도메인 대신 강조됨
- [ ] 특정 도메인 포지션이라면 해당 도메인 경력이 상단에 배치

## 3. 하이라이트 다양성

### 3.1 성과 유형 다양성
- [ ] 비용 절감 성과 존재
- [ ] 성능 개선 성과 존재
- [ ] 시스템 설계/아키텍처 성과 존재
- [ ] 자동화/효율화 성과 존재
- [ ] 품질 개선(에러 감소, 안정성) 성과 존재
- [ ] 5가지 유형 중 3개+ 커버됨

### 3.2 JD 어필 범위
- [ ] 백엔드 JD 공통 키워드 커버: API 설계, DB 최적화, 인프라, 테스트
- [ ] 시니어 JD 키워드 커버: 아키텍처, 기술 리드, 멘토링, 의사결정
- [ ] 스타트업 JD 키워드 커버: 빠른 개발, 풀사이클, 비용 효율
- [ ] 대기업 JD 키워드 커버: 대규모 트래픽, 안정성, 프로세스

### 3.3 다양한 JD에 어필 가능한 구성
- [ ] 특정 회사/포지션에만 어필하는 편향된 구성이 아님
- [ ] 기술 깊이(스페셜리스트)와 넓이(제너럴리스트) 균형
- [ ] 다양한 규모의 회사에 어필 가능 (스타트업~대기업)
- [ ] 산업/도메인 무관하게 기술력이 드러남

## 4. 기술 깊이 vs 넓이 균형

### 4.1 깊이 (Depth)
- [ ] 주력 기술(2~3개)에서 심화 경험이 드러남
- [ ] 주력 기술의 아키텍처 레벨 이해가 details에서 확인됨
- [ ] 동일 기술을 여러 프로젝트에서 다른 방식으로 활용한 경험
- [ ] 기술적 의사결정(왜 이 기술을 선택했는지)이 드러남

### 4.2 넓이 (Breadth)
- [ ] 백엔드 핵심 영역 커버: API, DB, 인프라, 메시징, 캐싱
- [ ] 프론트엔드 기본 이해 증거 (풀스택 경험 또는 협업 경험)
- [ ] DevOps/인프라 경험 (CI/CD, 클라우드, 모니터링)
- [ ] 다양한 DB 경험 (RDB, NoSQL, 캐시)

### 4.3 균형 판단
- [ ] 기술 나열이 "잡다한 경험"이 아닌 "폭넓은 역량"으로 읽힘
- [ ] 주력 기술이 명확히 구분됨 (Skills 섹션 카테고리 또는 순서)
- [ ] 보조 기술이 주력 기술을 보완하는 관계
- [ ] 시니어 레벨에 맞는 기술 깊이가 증명됨

## 5. 맞춤 PDF 추출 용이성

### 5.1 데이터 구조 필터링 적합성
- [ ] `featured` 플래그로 핵심 프로젝트 필터링 가능
- [ ] `techStack` 필드로 기술 기반 필터링 가능
- [ ] `tags` 또는 도메인 정보로 도메인 기반 필터링 가능
- [ ] experience `slug`로 특정 경력 추출 가능

### 5.2 맞춤 이력서 생성 시나리오
- [ ] "서버리스 전문" 이력서: 관련 프로젝트만 추출 가능한 구조
- [ ] "헬스케어 도메인" 이력서: 도메인별 필터링 가능
- [ ] "시니어 백엔드" 이력서: 아키텍처/리드 경험 중심 추출 가능
- [ ] 각 시나리오에서 highlights가 자연스럽게 연결됨

### 5.3 데이터 완결성
- [ ] 각 프로젝트가 독립적으로 이해 가능 (다른 프로젝트 참조 없이)
- [ ] highlights가 특정 프로젝트에 의존하지 않고 경력 레벨에서 이해 가능
- [ ] techStack이 프로젝트 레벨과 경력 레벨 모두에 존재
- [ ] period 정보가 모든 프로젝트에 존재하여 시간순 정렬 가능
