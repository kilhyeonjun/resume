# 한국어 문장 품질 체크리스트

## 1. 문체 일관성

### 1.1 highlights 문체
- [ ] 모든 highlights가 동일 패턴인지 확인
- [ ] 권장 패턴: "~하는 상황에서 ~하여 ~달성/실현/확보" (서술형 STAR)
  - 예시: "비용 급증 상황에서 읽기 방식을 전환하여 BigQuery 비용 82% 절감"
  - 안티패턴: "NestJS 유틸 10개 모듈로 사내 공통 라이브러리 생태계 구축" (Situation 없음)
- [ ] 혼재 검출: 서술형("~절감") vs 명사형("~구축", "~개발", "~실현") 종결이 섞여 있는지
- [ ] 경력별 highlights 문체가 통일됨 (4개 경력 모두 동일 패턴)

### 1.2 details 문체
- [ ] "제목: 설명" 형식이 전체적으로 일관
- [ ] 콜론 앞 제목은 명사구, 콜론 뒤 설명은 서술 또는 명사구 (혼재 허용)
- [ ] 동사 종결("~구현", "~개선") vs 명사 종결("~시스템", "~로직") — 경미한 불일치는 허용

### 1.3 description 문체
- [ ] 모든 experience의 description이 동일한 톤
- [ ] 문제→해결 구조 또는 서비스 설명 구조 중 하나로 통일

## 2. 자연스러움

### 2.1 조사 검증
- [ ] 을/를, 이/가, 에서/에 조사 누락 없음
- [ ] "수강생 300명+" → "수강생 300명+의" (조사 추가 시 더 자연스러운 경우 식별)
- [ ] 기술 용어와 한국어 조사의 결합이 자연스러움

### 2.2 주술 호응
- [ ] 주어와 술어의 호응 확인
- [ ] 장문(70자+)에서 주어가 불분명해지는 경우 식별
- [ ] 쉼표로 연결된 병렬 구조에서 주어 일관성

### 2.3 수식어 적절성
- [ ] "효율적", "안정적", "혁신적" 등 형용사가 구체적 지표 없이 사용되지 않음
- [ ] "End-to-End"와 상세 설명이 함께 있어 중복되는 경우
- [ ] "비용 효율적" 같은 모호한 표현 → 무엇의 비용인지 명확한지

## 3. 길이 균형

### 3.1 highlight 길이
- [ ] 각 highlight 1~2문장 (40~80자 권장)
- [ ] 100자 이상인 highlight 식별 → 분리 또는 축약 검토
- [ ] 같은 경력 내 highlights 길이 편차가 2배 이상이면 주의

### 3.2 detail 길이
- [ ] 각 detail 1문장 (30~80자 권장, 최대 100자)
- [ ] 하나의 detail에 2개 이상의 수치가 포함되면 분리 검토
- [ ] "제목: " 부분을 제외한 설명 부분의 길이 균형

### 3.3 description 길이
- [ ] 25~60자 범위
- [ ] 경력별 description 길이 편차가 과도하지 않음

## 4. AI 슬롭 검출

### 4.1 과장 표현
- [ ] "혁신적", "획기적", "최첨단" 등 이력서에 부적절한 과장 없음
- [ ] "완벽한", "최적의" 등 절대적 표현 지양
- [ ] "성공적으로" — 결과가 이미 성공을 암시하면 불필요

### 4.2 반복적 패턴
- [ ] 동일 접속사/연결어가 과도하게 반복되지 않음
- [ ] "~를 통해", "~기반으로" 패턴이 지나치게 많지 않음
- [ ] 불필요한 부연 설명 (이미 명확한 내용을 다시 설명)

### 4.3 구체성 vs 추상성
- [ ] 구체적 수치 > 형용사적 표현 (원칙)
- [ ] "대폭 개선" → 몇 % 개선인지
- [ ] "다수의 프로젝트" → 몇 개인지
