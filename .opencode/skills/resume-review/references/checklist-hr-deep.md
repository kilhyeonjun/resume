# HR 심층 분석 체크리스트

## 1. Summary 첫 문장 임팩트

### 1.1 첫 문장 분석
- [ ] 첫 문장이 "나는 누구이고 무엇을 잘하는가"를 즉시 전달
- [ ] 총 경력 연수 또는 핵심 도메인이 첫 문장에 포함
- [ ] 타겟 포지션 키워드가 첫 문장에 존재 (예: "백엔드 엔지니어", "서버리스 전문")
- [ ] 첫 문장만 읽어도 후보자의 레벨감이 느껴짐

### 1.2 Summary 전체 구조
- [ ] 3~4문장 이내로 간결
- [ ] 문장 1: 정체성 + 핵심 역량
- [ ] 문장 2~3: 차별화 포인트 또는 대표 성과
- [ ] 마지막 문장: 지향점 또는 가치관 (선택적)
- [ ] 과장 없이 사실 기반으로 작성됨

### 1.3 ko/en Summary 비교
- [ ] ko Summary의 핵심 메시지가 en에서도 동일하게 전달
- [ ] en Summary가 영문 이력서 관례에 맞는 톤 (직접적, 성과 중심)
- [ ] ko의 겸양 표현이 en에서 적절히 변환됨 (과도한 겸손 제거)

## 2. 채용담당자 7.4초 스캔 시뮬레이션

### 2.1 시각적 스캔 경로 (F패턴)
- [ ] 0~2초: 이름 + 직함 + 연락처 즉시 인지 가능
- [ ] 2~4초: Summary 핵심 문장 스캔 → "이 사람이 뭘 하는지" 파악
- [ ] 4~6초: Skills 섹션 스캔 → 기술 매칭 여부 판단
- [ ] 6~7.4초: 최신 경력 회사명 + 직함 확인

### 2.2 정보 밀도 검증
- [ ] 상단 1/3 영역에 핵심 정보 집중 (이름, Summary, Skills)
- [ ] 불필요한 장식/여백이 핵심 정보를 밀어내지 않음
- [ ] 스캔 시 눈에 걸리는 "앵커 포인트" 존재 (볼드, 수치, 기술명)
- [ ] 7.4초 내에 "더 읽고 싶다"는 동기 부여 가능

### 2.3 스크리닝 통과 요소
- [ ] JD 키워드 매칭: 타겟 포지션의 필수 기술이 Skills에 포함
- [ ] 경력 연수가 요구사항과 부합
- [ ] 최신 경력이 타겟 포지션과 관련성 높음
- [ ] "빨간 깃발" 없음 (긴 공백, 잦은 이직, 불명확한 역할)

## 3. STAR 임팩트 정량화 심층 분석

### 3.1 Situation 품질
- [ ] 문제의 규모/심각성이 명확 (예: "비용 월 $X 초과", "응답시간 N초")
- [ ] 비즈니스 맥락이 포함됨 (왜 이것이 문제였는지)
- [ ] 기술적 제약 조건이 언급됨 (선택적이지만 깊이 추가)
- [ ] Situation이 너무 길지 않음 (전체의 20~30%)

### 3.2 Task/Action 구체성
- [ ] "무엇을 했는지"가 아닌 "어떻게 했는지" 기술
- [ ] 사용한 기술/방법론이 구체적으로 명시
- [ ] 본인의 기여와 팀의 기여가 구분됨 (또는 리드 역할 명시)
- [ ] 의사결정 과정이 드러남 (왜 이 방법을 선택했는지)

### 3.3 Result 정량화 수준
- [ ] 모든 highlights의 80%+ 에 정량적 수치 포함
- [ ] 수치의 종류 다양성: 비용(%), 시간(%), 규모(건수), 품질(에러율)
- [ ] Before→After 형식으로 개선 폭이 명확
- [ ] 비즈니스 임팩트와 기술적 성과가 연결됨

### 3.4 수치 신뢰성
- [ ] 극단적 수치(95%+)에 맥락/근거 존재
- [ ] "약", "대략" 등 모호한 수식어 최소화
- [ ] 동일 성과의 수치가 highlights와 details에서 일치
- [ ] 수치가 프로젝트 규모/기간 대비 합리적

## 4. 경력 스토리라인 일관성

### 4.1 커리어 내러티브
- [ ] 전체 경력이 하나의 성장 스토리로 읽힘
- [ ] 각 이직의 동기가 암묵적으로 이해됨 (더 큰 규모, 새 도메인, 기술 성장)
- [ ] 경력 간 기술적 연결고리 존재 (이전 경력의 기술이 다음에서 발전)
- [ ] 도메인 전환이 있다면 자연스러운 브릿지 존재

### 4.2 일관성 검증
- [ ] position 명칭이 실제 역할과 부합
- [ ] 각 경력의 description이 전체 스토리라인과 조화
- [ ] highlights의 성과 수준이 경력 순서에 따라 성장
- [ ] 기술 스택의 발전이 시간순으로 자연스러움

### 4.3 공백/전환 처리
- [ ] 경력 간 공백 기간이 3개월 이상이면 설명 가능
- [ ] SI→서비스, 스타트업→대기업 등 전환이 긍정적으로 프레이밍됨
- [ ] 짧은 재직기간(<1년)이 있다면 성과로 보완됨

## 5. 성장 궤적 (주니어→미드→시니어)

### 5.1 역할 성장
- [ ] 초기 경력: 구현 중심 (개발, 코딩, 기능 구현)
- [ ] 중기 경력: 설계 + 구현 (아키텍처, 기술 선택, 최적화)
- [ ] 현재: 리드/설계 + 멘토링 + 의사결정 (시스템 설계, 팀 기여)
- [ ] 각 단계의 highlights가 해당 레벨의 기대치에 부합

### 5.2 기술 깊이 성장
- [ ] 초기: 프레임워크 사용 수준 (Express, Spring 등)
- [ ] 중기: 아키텍처 패턴 적용 (DDD, Event-Driven, CQRS)
- [ ] 현재: 시스템 설계 + 인프라 (서버리스, 분산 시스템, 비용 최적화)
- [ ] 기술 스택이 시간에 따라 모던화됨

### 5.3 임팩트 규모 성장
- [ ] 초기: 기능/모듈 단위 성과
- [ ] 중기: 서비스/시스템 단위 성과
- [ ] 현재: 조직/비즈니스 단위 성과
- [ ] 수치의 규모가 경력에 따라 커짐 (또는 깊이가 깊어짐)

## 6. 차별화 포인트

### 6.1 고유 강점 식별
- [ ] 다른 백엔드 개발자와 구분되는 1~2가지 핵심 차별점 존재
- [ ] 차별점이 Summary, Skills, highlights에서 일관되게 드러남
- [ ] 특정 도메인 전문성 (헬스케어, 교육, 게임 등)이 어필됨
- [ ] 기술적 깊이 (서버리스, EDA, 비용 최적화 등)가 구체적

### 6.2 차별점 증거
- [ ] 차별점을 뒷받침하는 프로젝트/성과가 2개 이상 존재
- [ ] 단순 기술 나열이 아닌 "이 기술로 무엇을 달성했는지" 증명
- [ ] 오픈소스 기여, 발표, 수상 등 외부 검증 가능한 증거 (있다면)

### 6.3 포지셔닝 명확성
- [ ] "이 사람은 ___를 잘하는 ___이다"로 한 문장 요약 가능
- [ ] 너무 넓은 포지셔닝 지양 ("풀스택 + DevOps + AI" 등)
- [ ] 타겟 포지션에 맞는 포지셔닝 (제너럴리스트 vs 스페셜리스트)
