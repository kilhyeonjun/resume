# 구조/레이아웃 체크리스트

## 1. 전체 구조

### 1.1 섹션 순서
- [ ] 경력 역순 정렬 (최신이 위)
- [ ] 섹션 순서 확인: Summary → Skills → Experience → Education → Awards/Certifications
- [ ] ko와 en의 섹션 순서 동일

### 1.2 skills 섹션
- [ ] 핵심 기술 7~15개 (카테고리 포함)
- [ ] 주력/보조 구분 또는 카테고리별 분류
- [ ] experience에서 실제 사용된 기술과 일치

### 1.3 교육/수상
- [ ] 교육 역순 정렬
- [ ] 수상/자격증 관련성 확인

## 2. 경력별 균형

### 2.1 highlights 개수 균형
| 재직기간 | 권장 highlights 수 |
|---------|-------------------|
| 9개월 미만 | 2~3개 |
| 9개월~1.5년 | 3~4개 |
| 1.5년~3년 | 4~5개 |
| 3년 이상 | 5~6개 |

- [ ] highlights 수가 재직기간에 비례
- [ ] 경력 간 highlights 수 편차가 합리적

### 2.2 projects 개수
- [ ] 경력별 프로젝트 수: 3~7개 범위
- [ ] 짧은 재직기간(<1년)에 프로젝트 6개+면 주의 (너무 많을 수 있음)
- [ ] 긴 재직기간(>2년)에 프로젝트 2개면 주의 (너무 적을 수 있음)

### 2.3 featured 비율
- [ ] 각 경력에서 featured=true 비율: 20~50%
- [ ] 최소 1개는 featured
- [ ] featured 프로젝트의 details가 non-featured보다 충실

### 2.4 details 개수
- [ ] 프로젝트별 details: 2~10개 범위
- [ ] 3주 프로젝트: 2~3개 적정
- [ ] 6개월+ 프로젝트: 3~6개 적정
- [ ] 동일 경력 내 프로젝트 간 details 수 편차가 합리적 (규모 비례)
- [ ] featured 프로젝트의 details가 가장 많거나 같음

### 2.5 description 길이
- [ ] 25~60자(ko 기준) 범위
- [ ] 경력별 description 길이 편차가 과도하지 않음
- [ ] 문제→해결 구조 또는 서비스 설명으로 일관

## 3. 프로젝트 순서

### 3.1 정렬 기준
- [ ] 시간순 또는 임팩트순 중 하나로 일관
- [ ] 동일 경력 내 모든 프로젝트가 같은 기준으로 정렬

### 3.2 겹침/의존관계
- [ ] 프로젝트 간 기간 겹침이 합리적으로 설명 가능
- [ ] 의존관계(A→B) 프로젝트가 시간순으로 자연스러움

### 3.3 시작/마지막 프로젝트
- [ ] 첫 프로젝트와 마지막 프로젝트가 재직기간의 시작/끝을 커버
- [ ] 빈 기간(프로젝트 공백)이 다른 진행 중 프로젝트로 커버됨

### 3.4 포지션-도메인 일치
- [ ] 프로젝트 도메인이 position 역할과 부합 (예: BE 포지션에 순수 FE 프로젝트 → 비중 축소 또는 기술 깊이 보강)
- [ ] 역할 불일치 프로젝트가 있으면 이유가 description에서 설명됨

## 4. 비중 분석

### 4.1 경력 간 비중
- [ ] 가장 최근/중요한 경력에 가장 많은 공간 (highlights + projects + details)
- [ ] 오래된 경력일수록 간결해지는 경향
- [ ] SI 경력과 서비스 경력의 비중이 포지션 목표에 맞게 조정

### 4.2 프로젝트 간 비중
- [ ] 3주짜리 소규모 프로젝트가 6개월+ 대형 프로젝트보다 비중이 크지 않음
- [ ] 단, 짧은 프로젝트라도 highlights와 연결되면 비중 유지 가능

### 4.3 techStack 비중
- [ ] 회사 전체 techStack: 10~20개 적정 (25개+ 면 핵심 기술 희석)
- [ ] 프로젝트 techStack: 15개 이상이면 주의
- [ ] 핵심 기술과 부수 도구가 혼재하여 핵심이 묻히지 않는지

## 5. 경력 성장 내러티브

- [ ] 경력 순서가 성장 스토리를 보여줌 (역할/책임/규모 증가)
- [ ] position 변화가 성장을 반영 (인턴 → 주니어 → 시니어 등)
- [ ] 기술 스택의 발전이 경력 순서와 일치 (Express → NestJS, 모놀리스 → 마이크로서비스 등)
