# UI/UX 체크리스트

## 1. 반응형 디자인

### 1.1 모바일 (< 640px)
- [ ] 모든 텍스트가 가로 스크롤 없이 읽힘
- [ ] 터치 타겟 최소 44x44px (버튼, 링크)
- [ ] 네비게이션이 모바일에서 사용 가능 (햄버거 메뉴 또는 축소)
- [ ] 테이블/리스트가 모바일에서 깨지지 않음
- [ ] 폰트 크기 최소 16px (iOS 줌 방지)

### 1.2 태블릿 (640px ~ 1024px)
- [ ] 레이아웃이 태블릿 너비에서 자연스러움
- [ ] 2컬럼 레이아웃이 적절히 조정됨
- [ ] 여백이 과도하거나 부족하지 않음
- [ ] 가로/세로 모드 모두 정상 표시
- [ ] 핵심 역량/카드형 그리드가 어색한 orphan 블록 없이 균형 있게 배치됨

### 1.3 데스크톱 (> 1024px)
- [ ] 최대 너비 제한으로 과도한 줄 길이 방지 (60~80자/줄 권장)
- [ ] 사이드 여백이 적절 (콘텐츠가 화면 가장자리에 붙지 않음)
- [ ] 와이드 스크린(1920px+)에서도 레이아웃 유지
- [ ] 호버 상태가 데스크톱에서 동작

## 2. 다크모드 일관성

### 2.1 색상 전환
- [ ] 모든 배경색이 다크모드에서 전환됨
- [ ] 모든 텍스트색이 다크모드에서 가독성 유지
- [ ] 보더/구분선 색상이 다크모드에서 적절
- [ ] 그림자(shadow) 효과가 다크모드에서 자연스러움

### 2.2 컴포넌트별 다크모드
- [ ] 네비게이션 바 다크모드 처리
- [ ] 스킬 뱃지/태그 다크모드 처리
- [ ] 카드 컴포넌트 다크모드 처리
- [ ] 링크 색상 다크모드에서 구분 가능
- [ ] 코드/기술명 하이라이트 다크모드 처리

### 2.3 전환 애니메이션
- [ ] 다크/라이트 전환 시 깜빡임(FOUC) 없음
- [ ] 전환 시 부드러운 트랜지션 적용
- [ ] localStorage 기반 초기 상태 복원이 즉각적

## 3. 타이포그래피 계층

### 3.1 헤딩 계층 (h1~h6)
- [ ] h1: 페이지 제목 (이름 또는 섹션 대제목) — 1개만 존재
- [ ] h2: 섹션 제목 (Skills, Experience, Education 등)
- [ ] h3: 하위 섹션 (회사명, 프로젝트명)
- [ ] h4~h6: 필요 시 세부 항목
- [ ] 헤딩 크기가 계층에 따라 시각적으로 구분됨

### 3.2 본문 텍스트
- [ ] 본문 폰트 크기 16px 이상
- [ ] 줄 높이(line-height) 1.5~1.75 (가독성)
- [ ] 단락 간 여백이 적절 (너무 붙거나 떨어지지 않음)
- [ ] 한국어/영어 폰트가 각각 적절 (Inter + 한글 폰트)
- [ ] 핵심 역량/요약 bullet이 좁은 컬럼에서 2~3줄 이상 과도하게 꺾이지 않음

### 3.3 강조/구분
- [ ] 굵기(bold)로 핵심 키워드 강조
- [ ] 색상으로 링크/인터랙티브 요소 구분
- [ ] 기술명/코드에 모노스페이스 폰트(JetBrains Mono) 적용
- [ ] 날짜/기간 등 메타 정보가 본문과 시각적으로 구분됨

## 4. 여백/정렬 일관성

### 4.1 섹션 간 여백
- [ ] 모든 섹션 간 여백이 동일 (일관된 spacing scale)
- [ ] 섹션 제목과 콘텐츠 사이 여백 통일
- [ ] 마지막 섹션과 푸터 사이 여백 적절

### 4.2 요소 간 여백
- [ ] 리스트 아이템 간 여백 일관
- [ ] 카드/블록 간 여백 일관
- [ ] 인라인 요소(뱃지, 태그) 간 간격 통일
- [ ] 아이콘과 텍스트 사이 간격 일관
- [ ] dense 섹션(핵심 역량, highlights)에서 항목 간격이 붙어 보이지 않음

### 4.3 정렬
- [ ] 텍스트 정렬 일관 (좌측 정렬 기본)
- [ ] 날짜/기간이 우측 정렬 또는 일관된 위치
- [ ] 기술 스택 뱃지가 정렬 규칙 준수
- [ ] 그리드/플렉스 레이아웃의 아이템 정렬 일관

## 5. 인터랙션

### 5.1 호버 상태
- [ ] 링크에 호버 시 시각적 변화 (색상, 밑줄)
- [ ] 버튼에 호버 시 시각적 피드백
- [ ] 카드/블록에 호버 시 미묘한 변화 (그림자, 배경)
- [ ] 호버 효과가 다크모드에서도 동작

### 5.2 포커스 상태
- [ ] 키보드 포커스 시 명확한 아웃라인
- [ ] 포커스 스타일이 브랜드 색상과 조화
- [ ] 포커스 순서가 논리적 (위→아래, 좌→우)
- [ ] 모달/드롭다운 내 포커스 트랩 (해당 시)

### 5.3 트랜지션
- [ ] 색상 변화에 부드러운 트랜지션 (150~300ms)
- [ ] 레이아웃 변화에 적절한 애니메이션
- [ ] `prefers-reduced-motion` 미디어 쿼리 대응
- [ ] 과도한 애니메이션 없음 (이력서 사이트 특성상 절제)

## 6. 시각적 계층구조

### 6.1 정보 우선순위
- [ ] 가장 중요한 정보(이름, 직함, Summary)가 시각적으로 가장 눈에 띔
- [ ] 핵심 성과(highlights)가 일반 설명(details)보다 강조됨
- [ ] featured 프로젝트가 non-featured보다 시각적으로 구분됨
- [ ] 연락처/링크가 쉽게 찾을 수 있는 위치

### 6.2 그룹핑
- [ ] 관련 정보가 시각적으로 그룹화됨 (근접성 원칙)
- [ ] 섹션 간 명확한 구분 (여백, 구분선, 배경색)
- [ ] 경력별 프로젝트가 해당 경력 아래 명확히 그룹화
- [ ] 기술 스택이 카테고리별로 그룹화
- [ ] 핵심 역량 카테고리가 배경/보더/간격/제목 대비로 명확히 분리됨
- [ ] 그리드 마지막 행이 깨질 때 시선이 분산되지 않도록 균형 유지

## 7. 첫인상 3초 테스트

- [ ] 3초 내에 "이 사람이 누구인지" 파악 가능 (이름 + 직함)
- [ ] 3초 내에 "무엇을 잘하는지" 파악 가능 (핵심 기술/도메인)
- [ ] 3초 내에 "경력 수준" 파악 가능 (연차 또는 시니어리티)
- [ ] 시각적 노이즈가 핵심 정보를 방해하지 않음
- [ ] 페이지 로딩 후 즉시 콘텐츠 표시 (SSG이므로 기본 충족)

## 8. 섹션 배치 순서

### 8.1 권장 순서
- [ ] Header (이름, 직함, 연락처)
- [ ] Summary/Introduction
- [ ] Skills (기술 역량 한눈에)
- [ ] Experience (경력 상세)
- [ ] Education
- [ ] Awards/Certifications
- [ ] 순서가 타겟 포지션에 최적화됨

### 8.2 순서 근거
- [ ] Skills가 Experience 앞에 위치하여 기술 스크리닝 용이
- [ ] 가장 어필하고 싶은 섹션이 상단에 배치
- [ ] ko/en 페이지의 섹션 순서 동일

## 9. 정보 구조(IA) 흐름

### 9.1 네비게이션 구조
- [ ] 메인 네비게이션에서 모든 주요 섹션 접근 가능
- [ ] 현재 위치 표시 (active state)
- [ ] 앵커 링크로 섹션 간 이동 지원
- [ ] ko/en 언어 전환 접근성

### 9.2 콘텐츠 흐름
- [ ] 상위→하위 정보 흐름이 자연스러움 (요약→상세)
- [ ] 경력 상세 페이지로의 진입점이 명확
- [ ] "더 보기" 또는 상세 페이지 링크가 직관적
- [ ] 뒤로 가기/상위 페이지 복귀 경로 존재

## 10. 콘텐츠 우선순위 배치

- [ ] Above the fold에 핵심 정보 (이름, 직함, Summary, Skills)
- [ ] 스크롤 없이 "이 사람을 더 알고 싶다"는 동기 부여
- [ ] 긴 경력 목록에서 최신/중요 경력이 먼저 노출
- [ ] 포트폴리오 링크가 관심 있는 리크루터에게 쉽게 접근 가능

## 11. F패턴/Z패턴 스캔 동선

### 11.1 F패턴 (텍스트 중심 페이지)
- [ ] 좌측 정렬로 F패턴 스캔 지원
- [ ] 각 섹션 첫 줄에 핵심 정보 배치
- [ ] 헤딩/볼드로 스캔 포인트 제공
- [ ] 긴 텍스트 블록 없이 시각적 끊김 존재
- [ ] 핵심 역량 섹션에서 카테고리 제목 -> bullet 요점 순으로 시선 흐름이 유지됨

### 11.2 Z패턴 (랜딩/헤더 영역)
- [ ] 좌상단: 이름/로고
- [ ] 우상단: 네비게이션/언어 전환
- [ ] 중앙: 핵심 메시지 (Summary)
- [ ] 하단: CTA (PDF 다운로드, 연락처)

## 12. CTA 배치

### 12.1 PDF 다운로드
- [ ] PDF 다운로드 버튼이 쉽게 발견 가능한 위치
- [ ] HR용/ATS용 구분이 명확 (또는 단일 다운로드)
- [ ] 다운로드 버튼의 시각적 강조 (primary 색상)
- [ ] 모바일에서도 다운로드 접근 가능

### 12.2 연락처
- [ ] 이메일/전화 등 연락처가 헤더 또는 쉽게 접근 가능한 위치
- [ ] 클릭 가능한 `mailto:` / `tel:` 링크
- [ ] GitHub/LinkedIn 등 프로필 링크 존재
- [ ] 연락처가 print 시에도 표시됨
