# HR/채용 관점 체크리스트

## 1. Highlights STAR 형식

### 1.1 구조 검증 (각 highlight에 대해)
- [ ] **Situation**: 무엇이 문제였는지/어떤 상황이었는지 명시
- [ ] **Task/Action**: 어떤 기술/방법으로 해결했는지 구체적
- [ ] **Result**: 수치적 결과 포함 (%, 배수, 시간, 비용, 건수)
- [ ] S/T/A/R 중 2개 이상 누락된 highlight가 없음

### 1.2 수치 포함 검증
- [ ] highlights 중 80% 이상에 정량적 수치 포함
- [ ] 수치 없는 highlight 식별 → 보강 가능 여부 판단
- [ ] "수십 초→즉시" 같은 모호한 수치 식별 → 구체화 권장

### 1.3 highlights 수 적절성 (재직기간 대비)
- 1년 미만: 2~3개
- 1~2년: 3~4개
- 2년 이상: 4~6개

## 2. Professional Summary

- [ ] 타겟 포지션 방향성 명시 (예: "서버리스/EDA 전문 백엔드 엔지니어")
- [ ] 핵심 차별화 포인트 1~2개 포함
- [ ] 총 경력 연수 또는 도메인 경험 언급
- [ ] 3~4문장 이내로 간결
- [ ] 과장이나 AI 슬롭 없이 사실 기반

## 3. Featured 프로젝트 선정

### 3.1 featured 비율
- [ ] 전체 프로젝트의 30~50%가 featured=true
- [ ] 경력별 featured 비율이 합리적 (최소 1개, 최대 프로젝트 수의 50%)

### 3.2 featured 적절성
- [ ] 가장 임팩트 큰 프로젝트가 featured=true
- [ ] featured 프로젝트에 수치적 성과가 있음
- [ ] featured 프로젝트의 details 수가 non-featured보다 많거나 같음
- [ ] 진행 중(미완성) 프로젝트가 featured인 경우 재검토

## 4. 7.4초 첫인상 테스트

리크루터가 이력서를 처음 보는 평균 시간 7.4초 내에:
- [ ] 이름, 현재 직함, 핵심 기술이 상단에 보임
- [ ] Summary가 3~4문장으로 핵심 전달
- [ ] 최신 경력이 가장 위에 위치
- [ ] F-shape 스캔 패턴 고려: 상단 좌측에 핵심 정보

## 5. 중복/반복 검출

### 5.1 허용 가능한 중복
- highlights(요약)와 details(상세)에서 동일 수치의 반복은 이력서 관례상 정상
- 단, highlight와 detail이 거의 동일 문장이면 문제

### 5.2 문제 되는 중복
- [ ] 동일 성과가 3곳 이상에서 반복 (highlights + details + description)
- [ ] 동일 기술 아키텍처 설명이 여러 경력에서 반복
- [ ] 2개 이상의 highlights가 동일 맥락을 다룸 (예: Deadlock 관련 2개)

## 6. 비즈니스 임팩트 명확성

- [ ] 기술적 성취와 비즈니스 가치가 연결됨 ("DB 최적화" → "응답시간 72% 단축")
- [ ] "대형 병원 계약 성사" 같은 모호한 표현 → 구체 수치 권장 ("N개사 계약")
- [ ] description에서 문제→해결 구조가 드러남 (기능 나열만 하지 않음)

## 7. 경력 내러티브

- [ ] 경력 progression이 성장 스토리를 보여줌
- [ ] 각 회사에서의 role이 이전보다 성장 또는 전문화됨
- [ ] SI → 서비스 전환 같은 커리어 전환이 있다면 자연스럽게 설명됨
