## Overview

Preserve the current KilPenguin dossier grammar while upgrading one thin project entry into an evidence-led case study. The first viewport must explain the problem, sole ownership, three verified engineering outcomes, and reachable public proof. No private financial data, operational credentials, or invented impact.

## Colors

Use near-black ink and white evidence surfaces. Blue is reserved for links and selected states; green communicates verified public boundaries. Status must never rely on color alone.

## Typography

Dense but readable editorial typography. Outcome values are prominent, supporting evidence remains plain language, and implementation vocabulary is deferred below the first fold.

## Layout

Keep the existing site header, language switch, dossier navigation, and previous/next project controls. Use one overview boundary diagram before deep technical prose, followed by three problem-solving stories and a compact public-evidence register.

## Shapes

Low-radius editorial cards, thin borders, no ornamental gradients, no glassmorphism, and no dashboard-style navigation replacement.

## Components

The proof link is the only high-emphasis action. Evidence cards group value, meaning, and provenance. Diagrams include title, caption, and adjacent text equivalent.

## Do's and Don'ts

- Do preserve existing portfolio routes, component grammar, KO/EN structure, print/PDF consumers, and public-safe claims.
- Do show synthetic/localStorage and private/public boundaries explicitly.
- Do not present test counts as user impact.
- Do not expose real family data, private repository paths, credentials, operational database details, or private application URLs.
- Do not invent adoption, savings, reliability, scale, or production-use metrics.
- Do not turn the page into a product dashboard or add a new global layout archetype.
