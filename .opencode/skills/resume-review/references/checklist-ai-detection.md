# AI 탐지 체크리스트

## 1. AI 슬롭 패턴 (영문)

### 1.1 Em Dash 과다
- [ ] Em dash(—) 사용 빈도 확인: 전체 highlights/details 중 20%+ 사용 시 주의
- [ ] Em dash가 쉼표나 괄호로 대체 가능한 경우 식별
- [ ] 동일 문장 내 em dash 2회+ 사용 없음
- [ ] ko에서는 em dash 대신 쉼표/괄호가 자연스러운지 확인

### 1.2 Rule of Three (3개 나열 패턴)
- [ ] "A, B, and C" 패턴이 과도하게 반복되지 않음
- [ ] 3개 나열이 2회 이상 연속 등장하면 주의
- [ ] 실제로 3개가 아닌데 억지로 3개로 맞춘 느낌 없음
- [ ] ko에서 "A, B, C를 통해" 같은 3개 나열 반복 확인

### 1.3 부풀린 상징어 (Inflated Symbolism)
- [ ] "journey", "landscape", "tapestry", "beacon" 등 추상적 은유 없음
- [ ] "transformative", "groundbreaking", "cutting-edge" 등 과장 형용사 없음
- [ ] "paradigm shift", "game-changer" 등 버즈워드 없음
- [ ] 이력서 맥락에서 불필요한 서사적 표현 없음

## 2. 홍보성/과장 표현

### 2.1 영문 과장
- [ ] "Spearheaded" — 실제 리드 역할이 아니면 부적절
- [ ] "Revolutionized" — 실제 혁신이 아니면 부적절
- [ ] "Pioneered" — 최초 시도가 아니면 부적절
- [ ] "Orchestrated" — 실제 오케스트레이션이 아니면 부적절
- [ ] 성과 수치가 뒷받침하지 않는 강한 동사 사용 없음

### 2.2 한국어 과장
- [ ] "혁신적인", "획기적인", "최첨단" 등 이력서에 부적절한 과장 없음
- [ ] "완벽한", "최적의", "최고의" 등 절대적 표현 없음
- [ ] "성공적으로" — 결과가 이미 성공을 암시하면 불필요
- [ ] "비약적인 성장", "눈부신 성과" 등 홍보성 표현 없음

### 2.3 수치 과장
- [ ] 99%+ 개선 수치에 맥락/근거 존재
- [ ] "수십 배", "대폭" 등 모호한 배수 표현 → 구체 수치로 대체 가능한지
- [ ] Before 수치가 의도적으로 나쁘게 설정되지 않았는지 (체리피킹)
- [ ] 비교 기준이 공정한지 (최악 케이스 vs 평균)

## 3. 모호한 귀속 (Vague Attribution)

### 3.1 주어 불명확
- [ ] "팀에서 ~했다" → 본인의 구체적 기여가 명시됨
- [ ] "~가 개선되었다" (수동태) → 본인이 개선한 것인지 명확
- [ ] "프로젝트를 통해 ~달성" → 본인의 역할이 드러남
- [ ] 팀 성과를 개인 성과처럼 기술하지 않음

### 3.2 역할 명확성
- [ ] "참여", "기여" 같은 모호한 역할 표현 최소화
- [ ] "설계", "구현", "리드", "주도" 등 구체적 역할 동사 사용
- [ ] 팀 규모나 본인의 포지션이 맥락에서 파악 가능
- [ ] "End-to-End" 표현 시 실제 전 과정을 담당했는지

## 4. AI 특유 어휘

### 4.1 영문 AI 마커 단어
- [ ] "delve" / "delve into" — 거의 사용하지 않는 일상 영어
- [ ] "leverage" — 과도 사용 시 AI 의심 (1~2회는 허용)
- [ ] "foster" — 이력서 맥락에서 부자연스러운 경우
- [ ] "tapestry" — 이력서에서 사용될 이유 없음
- [ ] "landscape" — 기술 맥락 외 사용 시 AI 의심
- [ ] "navigate" — 물리적 이동이 아닌 추상적 사용 시
- [ ] "realm" — 이력서에서 거의 사용되지 않음
- [ ] "utilize" — "use"로 충분한 경우 AI 의심
- [ ] "streamline" — 과도 사용 시 (1~2회 허용)
- [ ] "robust" — 과도 사용 시 (1~2회 허용)
- [ ] "seamless" / "seamlessly" — 과도 사용 시
- [ ] "comprehensive" — 과도 사용 시

### 4.2 영문 AI 구문 패턴
- [ ] "In order to" — "To"로 충분한 경우
- [ ] "It is worth noting that" — 불필요한 전치
- [ ] "This approach ensures that" — 설명적 과잉
- [ ] "By leveraging X, we were able to Y" — AI 전형 구문

## 5. 부정 병렬구문

### 5.1 영문 병렬 오류
- [ ] 리스트 항목의 문법 구조 통일 (모두 동사 시작 또는 모두 명사 시작)
- [ ] "Reduced X, building Y, and implementation of Z" 같은 혼재 없음
- [ ] 병렬 구조에서 시제 통일 (모두 과거형 또는 모두 현재형)

### 5.2 한국어 병렬 오류
- [ ] 나열 항목의 종결 형태 통일 ("~구현, ~개선, ~도입" 또는 "~했으며, ~했고")
- [ ] 조사 병렬 일관성 ("A를, B를, C를" 또는 "A, B, C를")
- [ ] 주술 호응이 병렬 구조에서도 유지됨

## 6. 접속부사 과다

### 6.1 영문 접속부사
- [ ] "Furthermore", "Moreover", "Additionally" 과다 사용 없음
- [ ] "Consequently", "Subsequently" — 이력서에서 불필요한 경우 많음
- [ ] 접속부사 없이도 문장 흐름이 자연스러운지 확인
- [ ] 전체 highlights/details 중 접속부사 시작 비율 10% 미만

### 6.2 한국어 접속부사
- [ ] "또한", "더불어", "나아가" 과다 반복 없음
- [ ] "이를 통해", "이를 바탕으로" 패턴 반복 확인
- [ ] "특히", "결과적으로" 과다 사용 없음
- [ ] 접속부사 제거해도 의미 전달에 문제없는 경우 식별

## 7. 피상적 -ing 분석

### 7.1 영문 -ing 남용
- [ ] "Leveraging X, achieving Y" — 분사구문 과다 사용 없음
- [ ] "By implementing X, resulting in Y" — 이중 분사 구문 없음
- [ ] 분사구문이 주절과 논리적으로 연결됨
- [ ] -ing 형태가 구체적 행동이 아닌 추상적 서술에 사용되지 않음

### 7.2 피상적 분석 패턴
- [ ] "~함으로써 ~를 달성" — 인과관계가 실제로 성립하는지
- [ ] 기술적 깊이 없이 표면적 서술만 있는 항목 식별
- [ ] "도입하여 개선" — 어떻게 도입했고 왜 개선되었는지 구체성 확인

## 8. 한국어 AI 패턴

### 8.1 AI 특유 한국어 표현
- [ ] "~의 여정" — 이력서에서 부자연스러운 서사적 표현
- [ ] "~를 통해" 과다 사용 (3회+ 시 주의)
- [ ] "핵심적인 역할" — "핵심 역할"로 충분, "적인" 불필요
- [ ] "~에 기여하였습니다" — 이력서 문체와 불일치 (경어체)
- [ ] "다양한 ~를 경험하며" — 구체성 없는 AI 전형 표현

### 8.2 한국어 AI 문장 구조
- [ ] 불필요하게 긴 수식어 체인 ("효율적이고 안정적인 확장 가능한 시스템")
- [ ] "~뿐만 아니라 ~까지" 패턴 반복
- [ ] "~함으로써 ~를 실현" — 과도한 인과 연결
- [ ] 한 문장에 3개+ 수식어가 붙는 경우

### 8.3 한국어 AI 어휘
- [ ] "선도적", "혁신적", "전략적" — 구체적 증거 없이 사용
- [ ] "심층적인", "체계적인" — 이력서에서 자기 평가성 표현
- [ ] "유기적으로", "시너지" — 비즈니스 버즈워드
- [ ] "패러다임", "생태계" — 기술 맥락 외 사용 시

## 9. 자연스러운 사람 문체 vs AI 문체 판별

### 9.1 사람 문체 특징 (긍정 신호)
- [ ] 불완전하지만 자연스러운 문장 구조
- [ ] 구어체적 표현이 적절히 섞임 (이력서 톤 내에서)
- [ ] 기술 용어와 일상 용어의 자연스러운 혼합
- [ ] 문장 길이의 자연스러운 변화 (짧은 문장 + 긴 문장)
- [ ] 개인적 관점/판단이 드러남 ("~가 더 적합하다고 판단")

### 9.2 AI 문체 특징 (부정 신호)
- [ ] 모든 문장이 비슷한 길이와 구조
- [ ] 과도하게 균형 잡힌 표현 (항상 장단점 모두 언급)
- [ ] 불필요한 한정어 ("다양한", "효과적인", "체계적인")
- [ ] 모든 항목이 동일한 패턴으로 작성됨 (변주 없음)
- [ ] 구체적 경험보다 일반적 서술이 많음

### 9.3 종합 판정
- [ ] 전체 이력서를 통독했을 때 "한 사람이 쓴 느낌"이 나는지
- [ ] 경력별로 문체가 급격히 달라지지 않는지 (일부만 AI 작성 의심)
- [ ] 기술적 깊이가 있는 부분과 표면적 서술 부분의 괴리 없음
- [ ] highlights와 details의 문체가 동일 저자 느낌
- [ ] ko와 en이 각각 자연스러운 해당 언어 문체인지 (번역체 아닌지)
